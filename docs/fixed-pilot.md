# Fixed pilot compatibility

`HermesRuns.connectPilot` supports the constrained Runs wrapper without opening extra API routes or accepting model/session/tool overrides. It submits exactly `{"input":"Reply with exactly HUB_HERMES_OK."}`. It checks authenticated `pilot_policy` (that exact input, tools zero, session overrides false, personal context false), required Bearer auth, submission/status and durable idempotency. It does not request `/v1/toolsets` in this mode, and never interprets 404 as tools zero. Standard mode still requires toolsets and its original fixed contract.

Completion requires exact `HUB_HERMES_OK` with actual runtime `openai-codex` / `gpt-6.1-sol`. Only then is the result normalized to the Hub's existing connectivity success text. Newline/extra output, model/provider mismatch and uncertain terminal status keep the execution slot/receipt for reconciliation.

The contract is `hermes-hub-fixed-pilot-v1`, distinct from standard mode. Original deadline/retention/contract and runtime scope remain persisted. Old/missing/foreign contracts are not migrated or blindly resubmitted. Lost admission acknowledgement is reconciled only with the same verified namespace, exact payload and original unextended deadline. Receipt reopen and known-ID polling are tested against a temporary mock API.

## Read-only independent inspector

`PilotInspector` checks local files/process independently of API-reported booleans. An operator must supply a private, independently reviewed policy; no policy generator, real profile defaults, secret reader, launcher, daemon or live worker entry point is installed. Supplying hashes of arbitrary code is not a safety review.

Required policy binds the approved loopback endpoint, dedicated profile, reviewed wrapper/config hashes, exact source commit, interpreter digest, complete executable/import dependency trees, credential metadata identity and durable idempotency DB identity. The derived scope hashes this policy so replacement of code, credentials, database namespace or configuration cannot silently reuse old receipts. Credential contents are never opened: only ownership, private permissions, device/inode/size/mtime/ctime are compared. PID files and nonsecret reviewed code/config are read. No shell command or destination comes from tasks.

The default macOS observer uses fixed bounded `ps`, `lsof` and read-only git commands to confirm PID/UID/start time/exact command, only the approved loopback listener, source commit. It avoids `git status` and disables fsmonitor for the metadata read, so local git status filters/monitors cannot become execution probes; the complete code-tree digest is the authoritative content check. It does not inspect process environment values. Two observations and file scans must agree. All regular files in approved code trees (including ignored code, bytecode and arbitrary archive names) are hashed; every file and directory must predate the process's earliest start second. Default snapshot trees reject owner/group/other-writable code files or directories and symlinks. Private/runtime data and unexpected changes reject evidence; explicitly reviewed system runtime and package-data handling are described below. Git metadata is excluded and must not be importable. Inspection returns null on any rejection; no warning-only fallback exists.

The policy review must cover **all Python import roots, interpreter/standard library/site-packages, `.pth`/archive/custom loader behavior and a sanitized trusted launch environment**. Undeclared import roots or an uncontrolled launch environment invalidate the prerequisite: this inspector does not independently discover `sys.path` or read secret-bearing environment values. Use an approved immutable executable snapshot and prevent bytecode/cache/code mutation after startup. The existing pilot's mutable checkout/venv may fail these strict checks; mock success does not establish its real policy. Pins must not be automatically refreshed after mismatch. An operator must review and approve any new namespace/policy and reconcile old receipts.

Evidence expires within 30 seconds. API policy corroborates the independent approved-code/process gate; it does not replace it. `ProcessProbe` injection is only a trusted testing seam. Production must use the built-in observer, not a fabricated observation. This source implementation and its dummy policies have not been run against a real profile, credential file, DB, process or model.

A subsequent read-only metadata check confirmed that the existing installed runtime does **not** satisfy this inspector: its checkout is owner-writable, its venv interpreter is a symlink, and its dependency tree exceeds the current 512 MiB per-tree limit. Its editable import hook points back to the mutable checkout. The dedicated API was stopped. A complete approved runtime snapshot and bounded compatibility review are still required before a live Hub roundtrip; copying the venv alone is insufficient. Existing Desktop files, authentication and configuration have not been changed.

## Bounded snapshot compatibility and preflight status

The tree limit remains 512 MiB by default. An explicitly reviewed tree may declare `maxBytes` up to 1 GiB; the policy permits at most four roots and at most 2 GiB of declared scan budgets in total. The 100,000 entries per tree and 64 MiB per file limits remain. All trees now reject effective-user write access, including ACL grants. Snapshot source/venv trees still additionally reject write permission bits and every symlink.

An explicit `systemRuntime` tree requires every entry to be root-owned and non-writable by the effective user; it retains content hashes and startup ctime checks. Only explicitly pinned system symlink aliases are allowed, and their canonical targets must lie in another measured system root or the same measured system root. Unknown aliases and changed targets reject. OS libraries supplied by the trusted macOS installation are a separate launcher-review prerequisite, not an implicit allowance for arbitrary native libraries.

`reviewedResources` can identify at most eight exact relative package-data directories named `logs`, `runtime` or `secrets`. This only resolves a name collision such as an SDK's public API-schema directory; every byte and entry is still measured and permission checked. It must never identify actual private or runtime data. `.env` files remain rejected and cannot be exempted. No subtree-exclusion mechanism is implemented.

During the authorized local preparation, a private code-only snapshot was created without copying credentials or execution history. Its editable hook was removed, and the isolated import preflight checked the actual fixed wrapper with user-site and bytecode writes disabled. It imported 1,307 modules without starting the API or creating an agent. The native loader also uses the macOS Python launcher executable, so measuring only the Python binary and standard-library directory is insufficient.

**The full live admission gate did not pass.** Measuring the whole installed Framework would include unneeded global packages, user-owned entries and more than 2 GiB of data. A proposed exclusion of disabled system site-packages and additional measured roots was rejected by automatic approval review and was not applied. The dedicated API was never started, no Hub task was submitted, no model run was performed, and no new authentication was issued. A narrower complete native/import manifest needs a separately approved boundary change and independent review before proceeding. The existing approved key and idempotency DB have not been reissued or initialized.
